# 编码 Agent 串行归并到用户目标分支

调优任务直接推进用户指定的原始仓库目标分支，不创建 Pika 长期集成分支。并发候选尝试排入唯一的归并队列；轮到某个候选时，编码 Agent 必须先将其工作重放到最新最佳已知版本并重新验证，再自动完成 Merge。这样保留 Agent 处理代码和冲突的能力，并让目标分支始终代表系统当前接受的最佳版本，代价是 Pika 必须严格串行化归并并可靠恢复 Agent 中断留下的 Git 状态。

## Consequences

- Pika 调度归并顺序，但所有 Git Merge 操作由编码 Agent 执行。
- 已接受结果会自动修改用户指定的原始分支，不等待用户手工确认。
- 候选相对旧版本的历史收益不能直接作为归并依据；必须相对归并时的最新版本重新测量。
