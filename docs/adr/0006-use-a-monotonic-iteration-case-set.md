# Use a monotonic Iteration Case Set

Iteration work uses a durable ordered subset of the Full Case Set: acceptance of a Baseline deterministically seeds at most ten Cases by SHA-256 of Case identity, every Iteration Round freezes the current subset, and a rejected Integration may append at most three previously unseen, ranked Regression Cases for future Rounds. Baseline Verification and Integration still cover the Full Case Set, candidate Iteration evidence must exactly cover its Round snapshot, and rejected Iterations may report incomplete evidence. This keeps Iteration cost bounded while learning from observed regressions without changing in-flight work or forgetting prior coverage; existing Optimizing workspaces require an explicit offline migration because silently choosing historical Iteration Cases would manufacture domain history.
